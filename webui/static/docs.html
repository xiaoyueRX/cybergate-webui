📖 CyberGate · 使用手册

通用手册。具体设备的架构、脚本清单、参数请以你自己的部署为准。

🧭 1. 访问入口

服务地址说明
控制台http://<手机IP>:<web_port>/全功能管理（本手册宿主）
代理面板控制台内「代理面板」Tab需设备上有 mihomo/clash 的 external-controller
网盘http://<手机IP>:<webdav_port>/WebDAV（需另启 webdav_server.py）

本地域名（如 k40s.com）解析依赖内置 DNS + 端口 53 重定向，见 docs/ADAPTING.md。不需要可忽略。

🛡️ 2. 面板与外部守护的关系

CyberGate 是观察与控制面板，本身不建立网络规则。CAKE/DSCP/NAT/DHCP/代理等 底座由你自己的 keeper 脚本或工具维护。面板读取它们的状态、并可开关部分动作。

因此：面板上某张卡片报错，通常意味着对应的外部脚本/二进制在你的设备上不存在 （config 里相应项留空即可，不影响其他功能）。

🚨 3. 排障思路

1. 先确认手机自身有网（蜂窝正常）。

2. curl http://127.0.0.1:<web_port>/api/status 看后端 JSON 是否正常。

3. 日志在 /data/local/tmp/cybergate.log。

4. 单个卡片异常 = 该命令/路径在你设备上不可用，见 docs/ADAPTING.md 逐项点亮。

📶 4. 无线参数建议（通用）

热点优先用 5GHz + 80MHz（延迟与吞吐均衡）；信道避开雷达段(52-64)与拥堵段， 用 iw dev wlan1 scan 或 Cellular/Wi-Fi 分析工具看邻居再定。

Wi-Fi 省电模式（power_save）会增加延迟抖动，做网关时建议关闭。

🔋 5. 供电

长期插电做网关，若设备支持旁路供电(Bypass)可保护电池。控制台总览显示温度/功率/电压。

💻 6. 技术架构

后端：单文件 Python（标准库），跑在设备上以 root 执行系统命令；也可在 PC 经 adb 远程管理。

前端：单页 HTML，全部相对路径调 REST API，天然跨设备。

流量记账：SQLite（自动建表建文件）。投屏：screencap 帧（可选 Pillow 压缩）。

接口清单见 docs/API.md，适配见 docs/ADAPTING.md。
